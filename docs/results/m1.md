# M1 test results

Recorded 2026-10-04 on the author's machine (Intel Core i7-13700H, Windows 11, Node.js 24,
TypeScript 7.0.2, fast-check 4.10.2). CI re-runs everything on Node.js 24 on every push.

## Tests: 16 passed, 0 failed

Command: `make test` (`npm test`: compile with `tsc`, then `node --test`).

### Unit tests

| Test | What it proves |
|---|---|
| local inserts and deletes behave like a string | Index-based editing on one replica works |
| characters are code points, so emoji are never split | `😀` is one character, not two UTF-16 halves |
| every character gets a unique id from its replica and Lamport counter | Ids `(a,1) (a,2) (a,3)`; each insert's origin is its left neighbour |
| receiving an op advances the Lamport clock past it | New local ids are always higher than anything seen |
| concurrent inserts at the same spot end in the same order everywhere | Deterministic tie-break |
| an insert next to a concurrently deleted character still lands in the right place | Tombstones keep positions resolvable |
| ops that arrive before their dependency wait, then apply | Reverse-order delivery works; pending buffer drains |
| applying the same op twice changes nothing | Duplicate delivery is harmless |
| malformed ops from a peer are rejected without changing the document | 10 malformed shapes, all `TypeError`, state untouched |
| a peer cannot grow the pending buffer without limit | Bounded buffer (`RangeError` past the limit) |
| local edits outside the document are refused | Range checks on insert, delete and replica name |
| text typed forwards concurrently at the same spot stays together | `ab` and `xy` merge to `xyab` on both replicas |
| known limitation: text typed backwards concurrently interleaves | Typed right-to-left, the same edits merge to `xayb`; Fugue (M2) fixes this, and this test will flip |

### Property tests (fast-check, 1,000 random schedules each)

Each schedule has 2 to 4 replicas and up to 60 random actions: inserts (including `é` and `😀`),
deletes, and deliveries that pick any waiting message, so messages arrive out of causal order. At
the end every inbox is flushed backwards and every operation is delivered a second time.

| Property | Result |
|---|---|
| All replicas converge to the same text, whatever the delivery order | 1,000 / 1,000 |
| No edit is lost and no deleted character comes back | 1,000 / 1,000 |
| A single replica behaves exactly like a plain string | 1,000 / 1,000 |

### Mutation check

To show the properties can actually fail, the compiled ordering code was broken on purpose and
the suite re-run (then rebuilt from source):

| Mutation | Tests that failed |
|---|---|
| RGA skip rule reversed (`> 0` to `< 0`) | 6 of 16 |
| Tie-break between equal counters removed | 4 of 16 |
